# DISPO GAME — FULL SYSTEM DESIGN PACKAGE V2

## Purpose
This package is the second-pass, implementation-oriented design expansion requested from `DISPO_GAME_NEW_CHAT_DESIGN_HANDOFF`.

It does **not** replace canonical repository authority. It is a proposed design layer for the Studio Hub to reconcile into the repository. Where this package labels something `CURRENT PROJECT DECISION`, it is restating the supplied handoff. Where it labels something `NEW PROPOSAL`, it is new design work. Where it labels something `VALIDATION RESULT` or `OUTSIDE RESEARCH`, it is explicitly identified as such.

## Non-negotiable boundary
**CURRENT PROJECT DECISION:** TFS v7.11.4 remains the recommendation authority. The game may change information, time, inventory, physical execution, customer response, staffing, progression, economy and management. It may not secretly rerank or replace TFS recommendation truth.

Canonical relationship:

`TrueCustomerProfile -> reveal process -> KnownCustomerProfile -> TFSInput -> canonical TFS -> player choice -> physical transaction -> outcome`

Hidden customer truth may be used after the fact for fictional narrative outcome and analysis, but never to alter active TFS ranking before the information is legitimately revealed.

## Major corrections from V1
- Standard shift arrival target reduced from 22–25 to approximately **18–20** after queue simulation.
- Queue pressure is now generated by phase-specific bounded-renewal arrivals, service-time distributions and explicit patience rather than hand-waved targets.
- Safety stock now responds to demand **and** lead-time uncertainty instead of using a fixed number of shifts.
- Customer generation now has constraint compatibility, reveal plans, viability classes, dialogue cooldowns and repeat lifecycle rules.
- Promotion scoring now has exact submetrics, anti-compensation floors and trial/proof shifts.
- Manager gameplay now has explicit staff/task/exception state machines and opportunity costs.
- Exploit analysis is expanded and bound to QA cases.
- QA uses a machine-readable fixture format and a TFS oracle capture process; no fake TFS expected output is invented.
