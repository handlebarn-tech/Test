# 09 — CONTENT LONGEVITY & REPLAYABILITY

## 1. Principle
Replayability comes from recombination of customer information, inventory, batches, traffic, staffing and future consequences. Do not add disconnected minigames to hide repetition.

## 2. Repetition risks and systemic answers

| Repetition risk | Counter-system |
|---|---|
| same customer wording | semantic dialogue families + cooldowns + repeat context |
| same recommendation answer | changing batches/inventory/constraints + Similar/Compare |
| weighing fatigue | skill speed, assists, packaged mix, delegation later |
| POS clicking | one-screen default; exceptions only when meaningful |
| restock chores | risk-based 2–4 decisions, delegation, proactive timing |
| predictable rush | bounded phase windows + seeded composition/events |
| solved staffing | capability/fatigue/delivery/traffic variation |
| solved ordering | uncertainty, lead time, supplier availability, batch/product turnover |
| progression dead zone | responsibility unlocks tied to competency |
| manager removes floor | intervention incentives and opportunity cost |

## 3. Player-experience arc

### 0–1 hour — learn the physical truth
Decisions:
- understand explicit customer requests;
- open/use TFS;
- retrieve correct product/batch;
- weigh/scan;
- complete transaction;
- respond to LOW stock.

Do not introduce ordering or staff planning.

### 1–5 hours — learn information value
Add:
- ambiguity 1–2;
- targeted questions;
- budget/avoidance;
- Similar/Compare;
- rush/recovery rhythm;
- proactive restock;
- first repeats.

Mastery signal: player asks fewer but better questions.

### 5–10 hours — learn triage
Add:
- multi-constraint requests;
- no-perfect-fit cases;
- broader categories;
- more batch variation;
- Senior/acting-lead tasks;
- role reassignment.

Mastery signal: player protects both service quality and queue flow.

### 10–20 hours — learn preparation
Add:
- Lead/AM;
- break planning;
- receiving;
- inventory exceptions;
- opening readiness;
- order recommendations;
- deal consequences.

Mastery signal: fewer emergencies because the player prepared.

### 20–50 hours — learn multi-shift optimization
Add:
- Manager authority;
- supplier/order uncertainty;
- staffing mix;
- merchandising access;
- persistent repeat-customer history;
- scenario/challenge variants.

Mastery signal: the player shapes future floor conditions while remaining capable of hands-on rescue.

### 50+ hours
Longevity depends on:
- inventory/product/batch data refresh;
- customer recombination;
- seeded challenge scenarios;
- self-improvement against shift analytics;
- management consequences.

Do not promise infinite novelty from a finite dialogue pool.

## 4. Systemic variety matrix
A shift generator combines one value from each dimension within compatibility limits:
- traffic shape;
- customer composition;
- ambiguity mix;
- inventory pressure;
- repeat mix;
- operational event;
- staff coverage;
- active deal;
- receiving status;
- product/category emphasis.

Even 4 meaningful values across 6 independent dimensions creates thousands of combinations; hard compatibility rules prevent nonsensical stacks.

## 5. Scenario mode
Curated deterministic scenarios serve both replayability and QA.

Core set:
- Morning Ramp
- Deli Rush
- Budget Night
- Low Stock
- Recovery Window
- Repeat Customer Day
- Similar Challenge
- Batch Change
- Delivery Collision
- Break Coverage
- Manager Intervention
- Order Consequence
- Deal Sell-Through
- No-Perfect-Fit Clinic
- Accuracy Challenge

Each scenario defines a benchmark and alternate goals; it does not create separate game rules.

## 6. Optional mastery objectives
Examples:
- <3% attributable abandonment;
- no critical stockout;
- >85 Service Judgment;
- zero wrong-batch corrections;
- two proactive restocks without throughput loss;
- correct informed no-sale;
- clear Rush 2 within 90 sec of phase end.

Objectives should rotate and remain optional after the associated competency is proven.

## 7. Repeat customers as longitudinal content
Repeat history creates new decisions without new mechanics:
- fast exact repeat;
- sold-out prior item;
- new batch of same strain;
- prior dissatisfaction;
- changed budget/use;
- customer trusts player and wants less explanation;
- customer wants comparison to previous purchase.

Cap repeats at 10–20% of Standard shift once the pool matures, with scenario overrides.

## 8. Batch turnover
Batch changes are especially valuable because they preserve product familiarity while changing authoritative current data. The game must surface batch identity clearly enough that the player learns not to treat strain name as permanent truth.

## 9. Content authoring budget
Prioritize content in this order:
1. semantic opener/response families;
2. repeat-history lines;
3. operational event reactions;
4. manager/staff escalation lines;
5. flavor lines.

More flavor lines cannot compensate for weak systemic variation.

## 10. Telemetry for repetition
Track per 50-customer window:
- opener family reuse;
- intent repetition;
- archetype run length;
- product chosen frequency;
- question frequency;
- resolution path distribution;
- restock count;
- event frequency.

Flag:
- any opener family >12% without scenario reason;
- same primary intent >25%;
- same top product >30% of sales where inventory variety should support more;
- >5 restocks/Standard shift;
- >2 identical operational events in 3 shifts.

## 11. Content expansion rule
A proposed feature earns implementation priority only if it:
1. creates a new decision;
2. has a cost/opportunity cost;
3. changes another existing system;
4. can be deterministically tested.

Otherwise prefer more data/content for existing systems.
