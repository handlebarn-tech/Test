## Deliverable
1. **Engine-level gate:** for every slice chip (DEC-017 golden parses) and a set of parser queries from `ParserGoldenTests`, the card list (strain keys, order, Ms to 4 dp, rep batch) is identical when computed (a) on a fresh catalog, (b) mid-shift after N seeded ticks with a full queue, (c) during the rush window, (d) with any `SliceConfig` gameplay keys changed (patience, rush multiplier, budgets, acceptThreshold). Inventory and pricing are held equal; the only allowed difference is a legitimate stock change, asserted separately (sell-out removes the batch exactly as `SoldOutBatch_NeverReturned…`).
2. **Input gate:** a test that `ShiftSim.Search` receives only the player's chip; the customer's hidden fields (`TrueFamily`, `Budget` when not stated) never change the result. Written so GAME-017 extends it to the KNOWN-profile composer (hidden avoidance / budget never appear in the composed query).
3. **Scenario harness:** a small JSON format (seed, catalog snapshot id, stock overrides, customer script: opener, true fields, player action list) + a runner that plays it on the pure sim and returns the TFS query used, the cards, and the outcome. One sample scenario: DP-020 (true sold-out excluded).
4. A one-line rule for future packets in the handoff: "every gameplay PR keeps `TfsParityGateTests` green".

## Validation
`studio.ps1 unity-compile`, `unity-test-edit` green; the gate fails if an engine call is routed through any gameplay value (prove it with a deliberately broken local variant, not committed). Engine/parser goldens unchanged. DEC-013 gate (≤ 2 editors).
