## Root cause
1. **The gate counts correctly.** `Wait-UnitySlot` queries WMI `Name='Unity.exe'`. That match is case-insensitive, so it also catches `unity.exe`. It then keeps only `*\Editor\Unity.exe` and drops `AssetImportWorker` and `serve`. Checked live: gate=1 when naive=3, and gate=2 when naive=5. Helpers (AutoQuitter/ILPP/ShaderCompiler) have other image names and are never counted.
2. **No bypasses.** No script in the repo launches Unity outside `studio.ps1`. `hub_guard.py` blocks direct calls from the main checkout.
3. **Slot hogging.** `Explore_TuningGrid` (marked `// TEMP exploration grid (removed before handoff)`, `[Test, Timeout(3000000)]` = 50 min) runs in the default EditMode suite. GAME-010 `unity-test-edit` took 517–970 s per run, against 20–45 s in every other worktree. It ran back-to-back: 7 runs from 02:03 to 03:18 local. One of the two slots is effectively GAME-010's alone, so ART-006, GAME-007 and the reviewers all share the other slot.
4. Real slot waits are rare in the logs (about 10 wait lines today). The three `slot wait timed out` results (10/29 22:16–22:45) came from the gate's own self-check, which used sub-minute timeouts, not from real stalls.

## Fix on this branch (recurrence guard)
- `Tools/Studio/studio.ps1`: `Invoke-Unity` now waits at most `unityRunTimeoutMinutes` (default **30**; the longest legitimate run today was about 16 min). On overrun it kills the editor tree with `taskkill /T /F`, which takes the import workers, ILPP and shader compiler with it. It then writes `failed: Unity run exceeded …` (exit 1). This lets no single run hold a DEC-013 slot without limit.
- `studio.config.example.json`: new `unityRunTimeoutMinutes: 30`. Existing gitignored `studio.config.json` files fall back to the same default.
- Self-check: `powershell -NoProfile -ExecutionPolicy Bypass -File Tools/Studio/studio_runlimit_test.ps1` → ALL PASS (fast run untouched; an overrunning parent and its helper child are both killed). studio.ps1 parses with 0 errors. No Unity run was made, because the guard blocks one here and the slots were busy.

## Recommendations for the Hub
1. **Urgent, GAME-010:** mark `Explore_TuningGrid` `[Explicit]` (or put it in its own `[Category("Explore")]`) right away, not only "before handoff". Normal `unity-test-edit` then drops from about 10 min to about 30 s and the slot is freed. Run the grid on purpose, with a `-testFilter`/category passthrough or inside an off-hours window.
2. Optional: give `studio.ps1` a `-TestCategory`/`-TestFilter` passthrough so sweeps can run alone. That needs a separate small task, so I left it out.
3. Hub tooling: count editors the same way the gate does (`*\Editor\Unity.exe`, excluding `AssetImportWorker` and `serve`), not by raw process name.
